# VDF — Village Defense Force Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a villager-faced militia unit (VDF) that garrisons villages once, patrols/protects them, answers raids, fights monsters + RU/US units, and stays neutral to players/PMC/BHQ — unrecruitable, inventory-free, unlimited ammo.

**Architecture:** `VdfUnitEntity extends RUunitEntity` inherits SEM's enemy-line combat core (unlimited ammo via `RuWeaponEquipper`, no `mobInteract`/inventory/owner). Targeting is per-entity via `setupRoleGoals()` — VDF swaps RU's enemy list for monsters/raiders/RU-US. Village garrisoning rides `EntityJoinLevelEvent` on villagers + a SavedData anchor set. Friendly fire on villagers is vetoed via TaCZ's `@Cancelable EntityHurtByGunEvent.Pre`. The villager face is a `RenderLayer` drawing `VillagerHeadModel` over the unit's head bone.

**Tech Stack:** Minecraft 1.20.1, Forge 47.4.0, Java 17, SEM (mapped jar in `libs/`), TaCZ, GeckoLib (armor items only).

**Spec:** `docs/superpowers/specs/2026-10-18-vdf-unit-design.md`

## Global Constraints

- Compile gate per AGENTS.md: `gradlew compileJava` must pass; no test infra exists.
- Java 17, Forge 47.4.0, MC 1.20.1 API names (`ServerLevel.getRaidAt`, `PoiTypes.MEETING`, `EntityJoinLevelEvent`).
- Mixin/patch members use `semcs$` prefix and `@Unique`; SEM internals accessed with `remap = false`.
- Commits authored as `Hoeng Reaksa <121419463+Poseidon9991@users.noreply.github.com>`; conventional types (`feat`/`chore`/`docs`).
- Every line of new Java gets a trailing `// comment` (repo convention since the zombie-drops pass).
- VDF joins NO `simpleenemymod:*_units` entity-type tag.

## Review Focus

- `setupRoleGoals()` may run before fields init (ctor-time virtual dispatch) — VDF's goals must not read instance fields.
- `UnitClass.of(vdf)` must resolve `VDF_UNIT` — VDF extends `RUunitEntity` but is not in the `ru_units` tag, so an `instanceof` check must run before tag checks (same guard BHQ needs vs `pmc_units`).
- `getRaidAt` returns raids only while active — goal must degrade gracefully (no raid → yield to patrol).
- `VillagerHeadModel` renders hat brim + head + nose + unibrow as one — hide `brim`/`hat` parts or the militia gets a villager straw-hat silhouette.
- SavedData anchors are BlockPos of the village bell — dimension-keyed storage on the *overworld* dataStorage (`PlayerChunkClaims` pattern), not the villager's level blindly.

**Interfaces:**
- `VdfPatrolGoal(VdfUnitEntity mob)` — Goal, `canUse` when no target + not raiding; waypoint = nearest unvisited `PoiManager` MEETING/BED/etc. POI, leash `ClassSystemConfig.vdfPatrolRadius()`
